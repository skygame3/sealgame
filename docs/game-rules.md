## 1. 구성 요소

| 요소 | 정의 |
|------|------|
| 보드 | 노드 집합 + 무향 엣지 집합으로 이루어진 그래프 |
| 인접 | 엣지로 직접 연결된 두 노드 |
| 돌 | 플레이어당 5개로 시작. **소모성 자원(병력)** |
| 결정 💎 | 포획 1회당 1개 획득. **기술 자원** |
| 잠긴 노드 ◇ | 보드 정의에 미리 지정. 💎3으로 개방 |
| 핵심 노드 | 동점 판정 기준 노드 |

**핵심 자원 구조**: 돌 = 병력(잃으면 영구 손실), 결정 = 기술(포획으로만 획득)

## 2. 노드 상태

```
LOCKED    → 잠김 (개방 전, 보드 정의에 지정됨)
EMPTY     → 비어 있음, 배치 가능
OCCUPIED  → 플레이어의 돌이 놓임 (P0 | P1)
SEALED    → 봉인됨, 배치 불가
```

상태 전이:
```
LOCKED  --💎3-->  EMPTY
EMPTY   --배치-->  OCCUPIED
OCCUPIED --포획--> SEALED   (돌은 영구 제거)
SEALED  --💎2-->  EMPTY     (돌이 놓이지 않음)
```

## 3. 턴 진행

자기 턴에 다음 중 정확히 하나를 수행:

1. **돌 놓기** — 손에 돌이 있고 `EMPTY` 노드가 있으면 그중 하나에 놓는다
2. **결정 사용** — 💎1 / 💎2 / 💎3 중 하나 (보유 결정이 충분할 때)
3. **패스** — 위 둘 다 불가능할 때 **강제**로 수행 (선택적 패스 아님)

행동 후 포획 판정을 자동으로 수행한다.

## 4. 포획 판정 ✅ RQ-002 확정

**조건**: 세 노드 A–B–C에 대해
- A와 B가 인접, B와 C가 인접
- A와 C는 **내 돌**, B는 **상대 돌**

→ B의 돌을 포획한다.

**판정 시점**: 내 돌이 새로 놓인 직후, **그 돌이 A 또는 C가 되는 모든 조합만** 검사한다.

**다중 포획**: 한 번의 배치로 여러 상대 돌이 조건을 만족하면 **모두 동시에** 포획한다.

**연쇄 포획 없음** ✅ 확정: 포획으로 판이 바뀐 결과 새 포획 형태가 생겨도 처리하지 않는다.
정의: **"한 번의 행동에서 발생한 포획만 처리한다."**

**포획 결과** (포획된 돌 1개당):
1. 해당 노드의 상대 돌 **영구 제거** — 상대의 손으로 돌아가지 않음 ✅ RQ-005 확정
2. 해당 노드를 `SEALED`로 변경
3. 포획한 플레이어가 결정 1개 획득

## 5. 봉인 ✅ RQ-001 확정

`SEALED` 노드는 배치 불가. 엣지 연결은 유지되지만 노드를 점유할 수 없다.

**포획 판정에서의 취급**: `SEALED` 노드는 어떤 플레이어의 돌도 아니므로 A·B·C 어느 위치도 될 수 없다.
즉 봉인은 그 자리를 지나는 모든 포획 라인을 끊는다.

**💎2 복구 시**: 해당 노드는 **`EMPTY`가 된다.** 복구한 플레이어의 돌이 놓이지 않는다.
(복구자의 돌이 즉시 놓이면 💎2가 과도하게 강력해지므로)

## 6. 결정 시스템 ✅ RQ-004 확정

| 비용 | 효과 | 대상 | 조건 |
|------|------|------|------|
| 💎1 | 즉시 돌 하나 추가 배치 | `EMPTY` 노드 | **손에 돌이 1개 이상 있어야 함** |
| 💎2 | 봉인 복구 → `EMPTY` | `SEALED` 노드 | — |
| 💎3 | 잠긴 노드 개방 → `EMPTY` | `LOCKED` 노드 | — |

**💎3 개방 대상** ✅ 확정: 보드 정의(`boards/*.json`)에 **미리 지정된 잠긴 노드(◇) 중 하나를 자유롭게** 선택.
인접 제한 없음. 임의의 노드를 새로 만드는 것이 아님.

**결정 사용도 하나의 행동**이며, 사용 후 포획 판정을 수행한다 (💎1 배치, 💎2 복구로 생긴 빈칸은 배치가 아니므로 포획 없음 — 💎1만 포획 판정 대상).

## 7. 종료 조건 ✅ RQ-003 확정

- 한 플레이어만 행동 불가 → **패스**하고 상대가 계속 진행
- **양 플레이어가 연속으로 패스하면 게임 종료**

구현: `GameState.consecutivePasses` 카운터. 패스 시 +1, 패스 외 행동 시 0으로 리셋.
`consecutivePasses >= 2`면 `isTerminal() === true`.

## 8. 승리 조건

1. 보드 위 자신의 돌 개수가 많은 플레이어 승리
2. 동점 → 핵심 노드를 점유한 플레이어 승리
3. 그래도 동점 → **후공 승리**

## 10. 🔬 밸런스 검증 최우선 항목

**RQ-005(포획 = 영구 제거)는 이 게임의 개성을 만드는 규칙이자 가장 큰 리스크입니다.**

우려: 3번 포획당한 플레이어는 돌 2개만 남고, 💎1은 손에 돌이 없으면 사용 불가 → 결정을 모아도
쓸 곳이 없는 "죽은 자원" 상태에 빠질 수 있음. 회복 불가능한 스노우볼.

**MVP에서는 영구 제거를 유지**하되, 대안을 **엔진 설정 플래그로 미리 구현**해 재작성 없이 A/B 비교한다:

```ts
interface RuleConfig {
  // 'place-from-hand'  : 💎1 = 손의 돌을 추가 배치 (기본값, MVP)
  // 'recover-and-place': 💎1 = 제거된 돌 1개를 손으로 되돌린 후 즉시 배치
  crystalPlaceMode: 'place-from-hand' | 'recover-and-place';
}
```

`recover-and-place` 모드에서 결정은 "병력 보충 자원"이 되어,
병력 회복 / 봉인 복구 / 노드 개방 사이의 기회비용 판단이 하나 더 생긴다.

**검증 지표** (`npm run sim` 자가대전 1000판, 두 모드 각각):

| 지표 | 경고 임계값 |
|------|-----------|
| 선공 승률 | 55% 초과 시 조정 검토 |
| 첫 포획 시점의 승률 상관 | 첫 포획자 승률 70% 초과 시 스노우볼 과다 |
| 돌 0개 상태로 남은 턴 수 | 평균 3턴 초과 시 "죽은 시간" 문제 |
| 미사용 결정 보유량 (종료 시) | 평균 2개 초과 시 결정이 죽은 자원 |
| 평균 총 턴 수 | 목표 범위 이탈 여부 |

결과에 따라 M2 종료 시점에 기본 모드를 확정하고 ADR로 기록한다.
